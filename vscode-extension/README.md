# aisanity — AI Memory Guardian (VS Code Extension)

Catches AI context drift and hallucination by validating every AI suggestion
against a plain-text project memory file (`.ai-memory.md`).

## Features

### Three Integration Layers

1. **Model Picker** — select aisanity from the VS Code model dropdown and ALL
   chat requests get proxied through validation automatically
2. **`@aisanity` Chat Participant** — type `@aisanity` before your question to
   validate that specific conversation
3. **MCP Server** — auto-registered tools (`aisanity_validate`, `aisanity_fix`,
   `aisanity_memory`) available to any AI agent

### Additional Features

- **Health Check** — run `aisanity: Health Check` to verify all components
  (memory file, main model, Ollama checker) are configured and responding
- **Command Palette** — `Init Project`, `Show Memory`, `Validate Selection`, `Health Check`
- **Status bar indicator** — shows whether the project has a memory file
- **Configurable disagreement flow** — enable/disable auto-correction when
  violations are found
- **Dynamic token limits** — queries the underlying model for its real context
  window size (Ollama `/api/show` or VS Code model API)
- **Zero external dependencies** — pure TypeScript, Node.js built-ins only

## Quick Start

### Step 1: Install and run Health Check

1. Install the `.vsix` extension
2. Run **aisanity: Health Check** from the Command Palette (Ctrl+Shift+P)
3. Review the output — it shows whether your Ollama server, models, and memory
   file are all configured correctly

### Step 2: Create project memory

Run **aisanity: Init Project** from the Command Palette, then edit the generated
`.ai-memory.md` with your project-specific rules:

```markdown
# PROJECT MEMORY — my-project

## Environment
- Language: Python 3.11
- Package manager: uv

## Critical Requirements
### Package Manager
- REQUIRED: uv
- FORBIDDEN: pip, pip3, conda
- Reason: Project uses uv for dependency management

## Forbidden Patterns
- Never use `requests` library — use `httpx`
- Never hardcode secrets — use environment variables
```

### Step 3: Add aisanity to the model picker

1. Open the Chat view (Ctrl+Shift+I)
2. Click the model picker dropdown at the top
3. Click **Manage Models** (gear icon)
4. Find **aisanity** in the provider list and click **+**
5. Enter your Ollama URL (e.g., `http://192.168.86.45:11434`) and model name (e.g., `devstral:24b`)
6. Select the newly added **aisanity** model from the dropdown
7. Start chatting — every response is now validated!

### Alternative: Use as chat participant

Instead of using the model picker, type `@aisanity` before any question:

```
@aisanity how do I install flask in this project?
```

Select **aisanity** as your model, then chat normally:

```

```

validates it against `.ai-memory.md`, auto-corrects if needed, and shows:

```

```

If the AI had suggested `pip install package-name`, aisanity catches it:

```

[validator: ollama / devstral:24b]

✅ Corrected and validated by aisanity (attempt 1) — now complies with project memory
```

## Requirements

- **Ollama** server running on LAN (default: `http://192.168.86.45:11434`)
- Recommended checker model: `devstral:24b`
- No Python required — the extension is 100% TypeScript/Node.js

## Settings

### Main Model (generation)

| Setting | Default | Description |
|---------|---------|-------------|
| `aisanity.mainModel` | `copilot:claude-opus-4.6` | Model for response generation |

The `aisanity.mainModel` setting controls which model generates responses when
aisanity is selected in the model picker:

| Value | Generation | Validation |
|-------|-----------|------------|
| `copilot:claude-opus-4.6` (default) | Claude Opus 4.6 | Ollama devstral:24b |
| `copilot:gpt-5.1` | GPT-5.1 | Ollama devstral:24b |
| `copilot:claude-sonnet-4` | Claude Sonnet 4 | Ollama devstral:24b |
| `ollama` | Ollama (`ollamaModel`) | Ollama (`ollamaModel`) |
| Any `vendor:family` | That VS Code model | Ollama (`ollamaModel`) |

**Example — use GPT-5.1 for generation:**
```json
{ "aisanity.mainModel": "copilot:gpt-5.1" }
```

**Example — use Ollama for everything:**
```json
{ "aisanity.mainModel": "ollama" }
```

### Checker Model (validation)

| Setting | Default | Description |
|---------|---------|-------------|
| `aisanity.ollamaUrl` | `http://192.168.86.45:11434` | Ollama server URL |
| `aisanity.ollamaModel` | `devstral:24b` | Ollama model used as checker/validator |
| `aisanity.githubModel` | `openai/gpt-4o-mini` | GitHub Models fallback model |
| `aisanity.memoryFile` | `.ai-memory.md` | Project memory filename |

### Behavior

| Setting | Default | Description |
|---------|---------|-------------|
| `aisanity.enableValidation` | `true` | Turn validation on/off globally |
| `aisanity.enableAutoCorrection` | `true` | Auto-correct violations (disagreement flow) |
| `aisanity.maxCorrectionRetries` | `1` | Max correction attempts (0–3) |
| `aisanity.showValidationBadges` | `true` | Show ✅/⚠️ badges in responses |
| `aisanity.validationBackend` | `ollama` | Backend: `ollama`, `github`, or `auto` |

### Configuration Examples

**Report-only mode** (see violations, no auto-fix):
```json
{ "aisanity.enableAutoCorrection": false }
```

**Maximum strictness** (3 correction attempts):
```json
{
    "aisanity.maxCorrectionRetries": 3,
    "aisanity.enableAutoCorrection": true
}
```

**Disable validation entirely** (pure proxy):
```json
{ "aisanity.enableValidation": false }
```

**Use a different Ollama checker model:**
```json
{ "aisanity.ollamaModel": "qwen2.5:32b" }
```

### Disagreement Flow

The disagreement flow is what happens when aisanity detects that the AI's response
violates your project rules:

```
Main model generates response
    ↓
aisanity validates via Ollama checker against .ai-memory.md
    ↓
❌ Violations found!
    ↓
Send violations back to the SAME main model
    ↓
Main model generates corrected response
    ↓
Re-validate (up to maxCorrectionRetries times)
    ↓
✅ Clean → show to user with ✅ badge
⚠️ Still has issues → show with ⚠️ warning
```

## How the Model Picker Works

1. You configure aisanity with your Ollama server URL and model name
2. Set `aisanity.mainModel` to choose your generation model (default: `copilot:claude-opus-4.6`)
3. Select aisanity as your active model in the chat picker
4. Every chat request from ANY participant goes through aisanity:
   - Your question is forwarded to the **main model** (with project memory injected)
   - The response is validated against `.ai-memory.md` via the **Ollama checker**
   - If violations → auto-corrected by the same main model
   - Clean response streamed back with ✅ badge
5. Token limits are queried dynamically from the underlying model

The model picker configuration takes priority over extension settings for
Ollama URL and model name.
